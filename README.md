# DCM 연동 현황 대시보드

[마스터 대시보드](https://yhbae106.github.io/SLA_DCM_2026_DW/) · [파트너 대시보드](https://yhbae106.github.io/SLA_DCM_2026_Partner/)

월별 DCM 원본과 마스터·유통협력사 조치 기록을 함께 조회합니다. 프런트엔드는 GitHub Pages, 인증·공용 저장은 기존 Google Apps Script와 Google Sheets를 사용합니다.

## 월별 자료와 출처

1. 담당자·업체/권역·기준월을 선택합니다. 자료 출처는 배포 기본 자료, 브라우저 보관 자료, Excel 반영본, 공용 반영 확인 상태를 구분하며 공용 저장 시각과 조회 확인 시각을 표시합니다.
2. 마스터 로그인 후 Excel을 선택합니다. 여러 파일 모두를 분석하고 월·업체·사업자번호·O/X 형식을 확인한 뒤 한 번에 브라우저에 반영합니다. 파일 읽기·분석·브라우저 저장 실패 시 이전 자료를 유지합니다.
3. 같은 월·업체/권역 자료는 새 파일로 교체합니다. 기존 표 형식과 `회사·도도매명·사업자번호·연동` 형식을 지원합니다.
4. Excel 반영 완료 이벤트가 발생한 경우에만 공용 저장을 시작합니다. 서버의 저장 확인 건수가 전송 건수와 같아야 성공으로 표시합니다. 저장 중 새 파일을 반영하면 최신 자료를 이어서 저장합니다. 실패 시 `공용 저장`으로 재시도합니다.
5. JSON 백업은 브라우저 미리보기 후 `공용 저장`으로 게시합니다. `초기 데이터 복원`은 확인창을 거쳐 브라우저의 월별 자료·Action 목록을 초기화하고 마스터 세션을 종료합니다. 복원 자체는 공용 자료를 게시하지 않습니다.

조회 중 새로 수정한 내용과 로그아웃 후 새 세션은 이전 응답으로 덮어쓰지 않습니다. 공용 저장 확인은 서버 저장 결과이며 다른 브라우저는 다음 조회에서 반영합니다.

## 조치 입력과 추가 협의 기록

- 공유키 로그인은 조회 인증입니다. 편집에는 개인 수정 PIN 또는 인증된 마스터 권한이 필요합니다. 배영훈은 전체, 정직한·임인숙은 본인 담당 거래처를 편집하며 서버에서도 권한을 확인합니다.
- 마스터의 원인·조치계획·상태 변경은 먼저 브라우저 미전송 목록에 보관하고 변경 필드만 순서대로 전송합니다. 저장 중 추가 입력도 이어서 저장하며 확인되지 않은 응답은 성공으로 표시하지 않습니다.
- 보관된 미전송 내용을 로그인만으로 자동 게시하지 않습니다. PIN 적용 후 `미전송 저장`을 사용할 수 있습니다.
- Google Sheet의 마스터 A:M과 파트너 N:T 입력은 별도 자료입니다. 파트너의 `수정 저장`은 해당 업체의 수정 필드만 제출하며 마스터 입력을 덮어쓰지 않습니다.
- 추가 SRM 협의는 별도 이력으로 보관합니다. 저장된 요청번호를 확인하며 같은 내용의 재시도는 중복 기록을 방지합니다. 저장 중 거래처를 바꾸거나 새 내용을 작성해도 다른 초안을 지우지 않습니다. 조회 실패 시 이전 정상 협의 이력을 유지하며 실패 상태를 표시합니다.
- 조치 입력, 조치 완료, 실제 X→O 개선을 구분합니다. 실제 연동 검증은 원본의 기준월 X 및 이후 최신월 O를 확인하는 기존 서버 규칙을 따릅니다.

## 계산·필터 기준

| 항목 | 기준 |
| --- | --- |
| 전체 연동률 | 그룹사별 O 합계 ÷ O와 X의 합계 |
| 미연동 X | 대웅제약·대웅바이오·한올바이오 X 평가건수 합계 |
| 연동 필요 절대처수 | 업체/권역·사업자번호별로 X가 하나라도 있으면 1처 |
| 공급 절대처수 | 업체/권역·사업자번호별로 O/X가 하나라도 있으면 1처 |
| X→O·O→X | 전월과 당월의 그룹사별 상태 전환 |
| 신규·중단 공급 | 업체/권역·사업자번호 단위 미공급↔O/X 전환 |
| 지속 X | 선택월까지 월별 이력이 연속해서 X인 기간 |
| 관리대상 | 진행중 + 완료 = 확인조치필요 + X→O 개선 |

같은 사업자번호가 다른 업체/권역에 있으면 각각 계산합니다. 정상 미평가와 연결 실패를 구분합니다. 실제 빈 공용 Action 목록은 0건으로 반영하고, 잘못된 응답은 이전 정상 자료를 유지합니다.

담당자 매핑은 임인숙(백제약품 원주·영남), 정직한(백제약품 대전·유진약품·아이팜코리아), 배영훈(백제약품 영등포·인천약품·복산나이스)입니다.

## 배포

`.github/workflows/pages.yml`은 Node 22에서 전체 하네스가 성공해야 Pages 아티팩트를 배포합니다. Pages는 GitHub Actions 배포 방식을 사용합니다. 변경 JS의 버전은 `20261021reliability1`입니다. 초기 로컬 자산은 기존 약 577.6KB에서 약 586KB로 늘었으며 추가 런타임 의존성 없이 590KB 한도를 유지합니다.

기존 API 버전 `20261008-seven-reasons-fast-v3` 계약을 사용하며 이번 변경은 Apps Script API를 변경하지 않습니다. 향후 `Code.gs` 변경 시 GitHub 반영과 운영 Apps Script 배포는 별도로 진행해야 합니다. 기본 월별 자료는 공개 정적 파일에 포함됩니다.
